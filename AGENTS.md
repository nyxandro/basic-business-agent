# Правила для агентов, которые работают в этом репозитории

Спецификация проекта одна — `docs/specs/[12.11.2026]-agent-base-architecture.md`: устройство, решения владельца и план по этапам. Новую работу вписывать в неё; отдельных файлов спецификаций не заводить. Ход работ — задачи GitHub (этап 1 — #1).

## Язык
- Ответы владельцу, документы в `docs/`, коммиты и задачи — по-русски.
- Тексты для людей в интерфейсе и ошибках — по-русски. Журналы и технические сообщения — по-английски, с кодом `APP_*`.

## Запуск
- `pnpm install` — заодно включает проверку перед отправкой (`core.hooksPath = tooling/git-hooks`).
- `cp .env.example .env`, затем `pnpm dev:db` — Postgres стенда разработки в Docker.
- `pnpm typecheck && pnpm lint && pnpm test` — обязательные проверки шага.
- `pnpm check:public` — проверка всей истории на данные заказчиков. Список имён — локальный файл `.public-check/forbidden-words.txt`, он не публикуется.

## Код
- TypeScript strict, Node 24 запускает `.ts` напрямую. Поэтому только стираемый синтаксис (`erasableSyntaxOnly`): без `enum` и без свойств в параметрах конструктора. Импорты — с расширением `.ts`.
- Файл кода — до 800 строк.
- Границы импорта проверяет `tooling/architecture`:
  - `core/` не импортирует плагины и зону установки;
  - плагины и зона установки берут из ядра только `core/<модуль>/public/`;
  - `web/` импортирует только `@bba/contracts`.
- Ошибки на границах — `AppError` из `core/errors/app-error.ts`: код, текст для человека, следующий шаг. Исходная ошибка сохраняется в `cause`.
- Обязательная настройка отсутствует — остановка с `APP_CONFIG_INVALID`, без значений по умолчанию.
- В `.env` — только секреты и адреса подключений. Поведение задаётся в `config/` и коде.

## База данных
- Миграции — SQL-файлы `core/db/migrations/NNNN_имя.sql`. Каждая выполняется в своей транзакции; применённую миграцию не меняем, добавляем новую.
- Схема `app` — наши таблицы и таблицы Better Auth, `mastra` — Mastra, `litellm` — LiteLLM.
- Тесты, которым нужна база, создают себе отдельную пустую базу через `createTestDatabase()` (`core/db/test-database.ts`) и удаляют её после себя.

## Тесты
- Рядом с кодом: `*.test.ts`. Сначала тест, который падает, потом код.
- Модель в тестах — заглушка: LiteLLM с `mock_response` или свой OpenAI-совместимый тестовый сервер. Настоящие ключи в тестах не нужны.

## Скиллы агента
- Скиллы проекта лежат в `.agents/skills`, ссылки на них — в `.claude/skills`, установка записана в `skills-lock.json`. Ставятся командой `DO_NOT_TRACK=1 npx skills add <репозиторий> --skill <имя> -a claude-code codex -y`.
- `mastra-*` — ссылки на документацию внутри установленных пакетов Mastra. После обновления Mastra сначала прочитать, что изменилось в этих скиллах, и только потом на них опираться.
- Скилл `copilotkit`: не запускать `copilotkit verify` и не подключать MCP-сервер CopilotKit без разрешения владельца — они отправляют данные в CopilotKit.

## Репозиторий публичный
- Данных заказчиков в нём быть не должно: в примерах только вымышленные организации и люди. Материалы заказчиков лежат в `inbox/`, эта папка в `.gitignore`.
