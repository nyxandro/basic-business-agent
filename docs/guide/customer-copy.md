# Копия для заказчика

Как из открытого репозитория собрать установку для одной организации, поставить её на сервер и потом подтягивать улучшения ядра. Пример — вымышленный заказчик «Альфа-Строй».

## Что где живёт

- **Открытый репозиторий** — ядро (`core/`, `web/`, `contracts/`), общие плагины (`plugins/`), демо-установка. Данных заказчиков в нём нет и быть не должно: перед каждой отправкой это проверяет `tooling/no-customer-data` (список имён — локальный файл `.public-check/forbidden-words.txt`, он не публикуется).
- **Копия заказчика** — закрытый репозиторий с общей историей. В ней меняется только зона установки: `config/`, `agents/`, `workflows/`, `skills/`, `custom/`. Код ядра не трогаем — тогда улучшения ядра приходят слиянием без конфликтов.

## 1. Сделать копию

```bash
pnpm customer:new alfa-stroy --plugins mail,bitrix24
```

- Копия появляется рядом с открытым репозиторием (`../alfa-stroy`, другое место — `--target <папка>`).
- Без `--plugins` команда спросит, какие плагины оставить; `--plugins ""` — ни одного.
- Невыбранные плагины удаляются первым коммитом копии. Открытый репозиторий подключён как `upstream`.
- Копируются только файлы из git: материалы заказчиков (`inbox/`) и секреты (`.env`) не переезжают.

Подключите закрытый репозиторий заказчика:

```bash
cd ../alfa-stroy
git remote add origin <адрес закрытого репозитория>
git push -u origin main
```

## 2. Агенты

Агент — папка `agents/<папка>/`:

- `agent.ts` — паспорт: `defineAgent({ id, name, description, plugins, readOnly, editable })`. Модель в паспорте не указывается: её выбирают в «Нейросети». `id` постоянный: им агент связан с отделами, правками промпта и расходами; папку можно переименовать.
- `instructions.md` — промпт агента. Правила ядра (роль, безопасность, подтверждения, данные) добавляются всегда, их не нужно повторять. По правилам ядра агент работает только в своей роли: с вопросом не по ней он отвечает одной фразой и называет подходящего агента сотрудника — название и `description` из паспорта. Поэтому в промпте опишите, чем агент занимается, а если граница неочевидна — и чем не занимается (например, «договоры не проверяешь — это к юристу»). Администратор правит промпт на странице агента в админке.
- `tools/` — свои инструменты агента, `subagents/` — подагенты.
- Скиллы (методики компании) в папках агентов и плагинов не лежат: исходник скилла — папка в `skills/` репозитория, `pnpm skills:pack` собирает из неё файл `.skill`, администратор загружает его в «Скиллы» и отмечает агентов, которым он нужен (новый скилл ни к одному агенту не привязан); у сотрудника скилл работает через агента — кому агент доступен, задаётся на странице агента, во вкладке «Доступ»: вся организация, отделы и сотрудники по имени. Документы Word, Excel, PowerPoint и PDF агент читает и делает системными скиллами ядра (`core/system-skills/`): они стоят у всех, их не нужно загружать и нельзя выключить; своим скиллам нельзя давать их имена (`docx`, `pptx`, `xlsx`, `pdf`). Папка `skills/` внутри агента или плагина, оставшаяся с этапа 1, останавливает запуск с подсказкой.
- `readOnly` — инструменты, которые только читают: они работают без «Да». Всё остальное ждёт подтверждения сотрудника.
- Что агенту можно — интернет (поиск и страницы) и запуск программ — включено у каждого нового агента; ненужное администратор выключает на странице агента («Настройки» → «Что агенту можно»). Подагенты работают с выключателями основного агента. Имена `web_research`, `web_search`, `web_fetch` заняты ядром — свой инструмент так назвать нельзя.

Уберите удалённые плагины из `agents/*/agent.ts` — иначе запуск остановится с `APP_CONFIG_INVALID` и назовёт файл и поле.

## 3. Настройки установки

- `config/app.ts` — название организации, часовой пояс (месячные лимиты обнуляются в 00:00 1-го числа по нему), что скрывать от модели с самого начала, стартовые лимиты. Дальше маскирование и лимиты меняет администратор в админке.
- Моделей в файлах нет: администратор добавляет их в «Нейросети» — ключ провайдера, цены в рублях, основная и запасная модель. Ключи хранятся зашифрованными в базе, LiteLLM получает их от сервера. Подписку ChatGPT подключают там же: «Подписка ChatGPT» в форме модели (например, `chatgpt/gpt-5.4`, без ключа и цен) и аккаунты в «Пуле аккаунтов подписки» — входом по коду на сайте OpenAI. Правила OpenAI об использовании личных подписок в чужом продукте не проверены — решение за организацией. Файл `config/models.ts` из этапа 1 нужно удалить: с ним запуск остановится и подскажет, что делать.
- `config/plugins.ts` — настройки оставленных плагинов (каждый проверяет свои при запуске).
- `.env` — только секреты и адреса подключений; поведение задаётся в `config/` и коде.

## 4. Проверить локально

```bash
cp .env.example .env && pnpm install && pnpm skills:setup
pnpm dev
pnpm admin:create admin@example.com "Администратор"
```

В админке: «Нейросеть» → модель, её ключ и цены (первая модель с картинками сама станет основной); «Скиллы» → скиллы компании (скиллы документов уже стоят); отделы → сотрудники и агенты отделов, роли, лимиты, профиль организации. В чате проверьте агентов; действие во внешней системе должно спрашивать «Да».

## 5. Поставить на сервер

Сервер — одна машина с Docker (по оценке спецификации: 4 ядра, 8 ГБ).

```bash
cp deploy/.env.example deploy/.env       # заполните: пароли, секреты, ключ шифрования, соль LiteLLM, адрес сайта
docker compose -f deploy/compose.yaml up -d --build --wait
docker compose -f deploy/compose.yaml exec app node core/cli/admin.ts create admin@alfa-stroy.example "Администратор"
pnpm smoke                               # проверка сборки и изоляции на копии установки
```

- Модели меняются в «Нейросети» без перезапуска. Сервер при каждом старте сверяет их с LiteLLM. `LITELLM_SALT_KEY` шифрует ключи провайдеров в базе LiteLLM: после добавления моделей его нельзя менять.
- Поиск в интернете — контейнер `searxng` установки (бесплатно, без ключей; настройки движков — `deploy/searxng/settings.yml`). `SEARXNG_SECRET` в `deploy/.env` — любая случайная строка от 32 знаков. Поисковики выдачи режут сервер капчей по-разному: если поиск у агентов начал возвращать пустоту (журнал `web_search_failed`), поменяйте набор движков или подключите платный поисковик через LiteLLM.
- Аккаунты ChatGPT: файлы входа — в томе `chatgpt-auth`, LiteLLM сам обновляет в них токен. Том не удаляйте без нужды: при старте сервер восстановит файлы из базы, но если LiteLLM успел обновить токен после последнего старта, аккаунту понадобится «Войти заново».
- Адрес сайта: `SITE_ADDRESS` — доменное имя (Caddy сам получит сертификат HTTPS) или `:80` за локальным портом. `APP_PUBLIC_URL` должен с ним совпадать.
- Голосовой ввод: браузер даёт микрофон только сайту на https (и `localhost`), поэтому установке нужен домен с сертификатом. Микрофон появляется у сотрудников, когда в «Нейросети» выбрана модель распознавания речи; без неё кнопки нет.
- Наружу открыт только Caddy: интерфейс и `/app/api`. Адрес учёта расходов LiteLLM (`/app/api/internal`) снаружи недоступен.
- Песочница скриптов скиллов работает внутри контейнера приложения на bubblewrap; контейнеру подключён профиль `deploy/seccomp-bwrap.json` (стандартный профиль Docker плюс 7 системных вызовов изоляции). Если на сервере bubblewrap запрещает AppArmor (так бывает на Ubuntu 24.04) — запасной путь описан в спецификации, раздел 8.9.
- Ключ шифрования: `APP_ENCRYPTION_KEYS="2:<новый>,1:<старый>"` — новый шифрует, старый ещё расшифровывает. Потеря ключа — потеря сохранённых личных доступов сотрудников, паролей почты и ключей хранилища.
- Файлы разговоров и проектов по умолчанию лежат на диске сервера (том рабочих папок). Чтобы держать их в S3 (Yandex Object Storage, Selectel, VK Cloud, Timeweb или любое S3-совместимое), суперадминистратор подключает бакет в админке: «Система → Хранилище файлов» — пустой бакет и ключ с правами на чтение и запись; файлы переедут сами. На диске тогда остаются только рабочие копии папок на время работы агента. Нужен свободный диск на самые большие проекты, с которыми работают одновременно.
- Почту каждый сотрудник подключает сам в «Настройки → Подключения». Вход через сайт Google, Microsoft или Яндекса включает администратор в «Подключения → Почта сотрудников»: приложение заводится у сервиса один раз, адрес возврата — `APP_PUBLIC_URL` + `/app/api/mail/oauth/callback` (показан там же с кнопкой «Скопировать»). Outlook и Microsoft 365 без этого не подключаются: паролей программам Microsoft не выдаёт. Серверу нужен выход в интернет к почтовым серверам по портам 993 и 465/587.

## 6. Обновления ядра

```bash
git fetch upstream
git merge upstream/main
pnpm install && pnpm typecheck && pnpm lint && pnpm test
docker compose -f deploy/compose.yaml up -d --build --wait   # миграции базы выполняются при старте, данные сохраняются
```

## 7. Улучшения — обратно в открытый репозиторий

Улучшили общий плагин или ядро в копии — перенесите изменение в открытый репозиторий отдельной веткой, без файлов и данных заказчика. Решение, нужное только этому заказчику, остаётся в его копии (`custom/`, его агенты и скиллы).
