# basic-business-agent

Лёгкая открытая база, из которой под каждую организацию быстро собирается свой бизнес-агент:

- веб-чат с интерактивными ответами: таблицы, графики, карточки, выбор, формы;
- сотрудники с ролями и отделами, админка без разработчика;
- учёт и лимиты расходов на модели, личный остаток у каждого сотрудника;
- подключение к CRM и почте под личным доступом сотрудника;
- каждое действие во внешней системе — только после «Да» сотрудника, с записью в журнал;
- фоновые задачи по расписанию и событиям; личная память; чтение PDF, Word, Excel и сканов;
- скрытие персональных данных от модели (паспорт, СНИЛС, карты, ИНН, телефоны, почты).

Стек: TypeScript, [Mastra](https://mastra.ai), CopilotKit 2 (AG-UI), Better Auth, LiteLLM, Postgres, Docker, Caddy.

**Состояние:** ядро реализовано по спецификации [`docs/specs/[12.11.2026]-agent-base-architecture.md`](docs/specs/%5B12.11.2026%5D-agent-base-architecture.md); ход работ — задача #1.

## Как устроено

```text
Браузер ──HTTPS──> Caddy (интерфейс; наружу только /app/api)
                     └──> приложение: свой сервер Hono + Mastra + CopilotKit runtime
                            ├──> Postgres + pgvector (схемы app, mastra, litellm)
                            ├──> LiteLLM ──> провайдеры моделей (личный ключ и бюджет у каждого сотрудника)
                            ├──> песочница bubblewrap: своя папка у сотрудника, без сети
                            └──> MCP-подключения к системам организации
```

Ядро (`core/`, `web/`, `contracts/`) и общие плагины (`plugins/`) — открыты. Установка конкретной организации — это её копия репозитория, где меняется только «зона установки»: `config/`, `agents/`, `workflows/`, `skills/`, `custom/`.

## Запуск для разработки

Нужны: Node 24, pnpm 11, Docker, bubblewrap (Linux; на macOS — встроенная изоляция), [uv](https://docs.astral.sh/uv/) для Python скиллов.

```bash
pnpm install                 # заодно включает проверку перед отправкой (нет ли данных заказчиков)
cp .env.example .env         # заполните: секреты — openssl rand -base64 48, ключ шифрования — openssl rand -base64 32
pnpm skills:setup            # Python-библиотеки для чтения документов
pnpm dev:db                  # Postgres и LiteLLM с моделями-заглушками для тестов
```

Демо с настоящей моделью:

```bash
pnpm dev                                         # LiteLLM установки, сервер (:3000) и интерфейс (http://localhost:8080)
pnpm admin:create you@example.com "Ваше Имя"     # печатает ссылку-приглашение суперадминистратора
```

Откройте ссылку, задайте пароль. В «Нейросети» добавьте модель: провайдер и модель (`openai/gpt-4.1-mini`), ключ провайдера, цены в рублях — сервер проверит ключ и передаст модель в LiteLLM; выберите её основной. Затем в «Отделах» создайте отдел, добавьте себя и агента «Общий помощник» — он появится в «Агентах».

Без ключа провайдера — стенд с моделью-заглушкой, которая отвечает по ключевым словам («таблица», «график», «карточка», «выбор», «форма», «письмо», «сделки», «почтальон»):

```bash
pnpm stand       # сервер на свежей тестовой базе (удаляется при остановке)
pnpm dev:web     # интерфейс: olga@example.com, petr@example.com или igor@example.com, пароль correct-horse-battery
```

## Проверки

```bash
pnpm typecheck && pnpm lint && pnpm test   # обязательные: типы, правила и границы импорта, тесты сервера и интерфейса
pnpm test:e2e                              # сквозные сценарии в браузере на стенде с моделью-заглушкой
pnpm smoke                                 # сборка образов и проверка установки в Docker
pnpm check:public                          # вся история — без данных заказчиков
```

## Установка у организации

`deploy/compose.yaml`: Postgres, LiteLLM, приложение с песочницами, Caddy — с потолками памяти, чтобы всё помещалось на сервер 8 ГБ.

```bash
cp deploy/.env.example deploy/.env          # заполните
docker compose -f deploy/compose.yaml up -d --build --wait
docker compose -f deploy/compose.yaml exec app node core/cli/admin.ts create admin@example.com "Администратор"
```

Подробно — [копия для заказчика](docs/guide/customer-copy.md). Как написать плагин — [docs/guide/plugins.md](docs/guide/plugins.md).

## Структура

```text
core/        ядро: сервер, вход и роли, чат, подтверждения, фоновые задачи, модели и лимиты, маскирование, подключения, песочница
web/         интерфейс: чат и блоки, «Ждёт подтверждения», настройки, админка
contracts/   схемы данных, общие для сервера и интерфейса
plugins/     общие плагины (в шаблоне — пример example-notes)
config/      настройки установки: организация, модели, плагины
agents/      агенты установки (в шаблоне — «Общий помощник»)
deploy/      Docker: образы, compose, Caddy, профиль seccomp, smoke.sh
tests/       демо-установка, стенд и сквозные сценарии
tooling/     проверки границ импорта, данных заказчиков, сборка профиля seccomp
```
