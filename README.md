# basic-business-agent

Лёгкая открытая база, из которой под каждую организацию быстро собирается свой бизнес-агент:

- веб-чат с виджетами: агент сам собирает в ответе экран из 43 готовых элементов — калькулятор с ползунками, сравнение вариантов, сводку с графиком, форму, таблицу, формулы; итоги пересчитываются в браузере, кнопки и формы отправляют агенту сообщение с выбранными значениями; у каждого агента выключатель «Виджеты в чате»; светлая и тёмная тема, телефон;
- проекты разговоров с инструкциями и файлами — создатель открывает их коллегам, отделам или всей организации; у каждого проекта корзина файлов на 30 дней, проекты уходят в архив, а не удаляются сразу; у разговора без проекта своя папка — файлы разных разговоров не путаются, файл из прошлого разговора агент берёт копией; черновики агента (скрипты сборки, снимки страниц) лежат отдельно и убираются сами через месяц без изменений; поиск по своим разговорам, проектам и документам — с опечатками, в другой форме слова, транслитом и в другой раскладке; голосовой ввод;
- сотрудники с ролями и отделами, админка без разработчика: модели и их ключи и пул аккаунтов подписки ChatGPT («Нейросеть»), скиллы файлом `.skill`, фоновые задачи с областью, страница каждого агента (инструкции, модель и подсказки, свой значок — иконка или картинка), вид чата («Интерфейс»: показывать значки агентов или нет);
- учёт и лимиты расходов на модели в рублях, личный остаток у каждого сотрудника;
- подключение к CRM и почте под личным доступом сотрудника: почта подключается в пару шагов — по адресу сервер сам находит настройки (Яндекс, Mail, Gmail, Outlook/Microsoft 365, iCloud, Рамблер, Yahoo, домены организаций и любая почта по IMAP/SMTP), вход через сайт сервиса или пароль приложения; агент читает, ищет, сохраняет вложения и отправляет письма только после «Да»;
- папка с компьютера сотрудника у проекта: агент смотрит, ищет и читает нужные файлы через браузер, заранее ничего не копируется;
- хранилище файлов: диск сервера или S3 (Yandex Object Storage, Selectel, VK Cloud, Timeweb и любое S3-совместимое) — подключается в админке, после чего файлы хранятся только там;
- каждое действие во внешней системе — только после «Да» сотрудника, с записью в журнал;
- фоновые задачи по расписанию — у каждого сотрудника области от его имени; память: у каждого проекта своя — агент сам записывает ключевые факты о работе, участники видят и правят записи на странице проекта, — и личная о самом сотруднике в «Моей памяти»; каждая запись видна строкой в чате; документы Word, Excel, PowerPoint и PDF — агент читает, делает и правит их (системные скиллы Anthropic, всегда включены), распознаёт сканы и отдаёт готовый файл кнопкой «Скачать»; документ из ответа открывается в просмотрщике, где на страницах можно обвести, подчеркнуть, поставить стрелку и подписать правку — «Отправить агенту» уходит одним сообщением с картинкой пометок и текстом под ними, агент правит файл;
- скрытие персональных данных от модели (паспорт, СНИЛС, карты, ИНН, телефоны, почты);
- интернет агента: поиск и чтение страниц и документов по ссылкам — через помощника-исследователя, который видит только задание и возвращает ответ с источниками; поиск — свой SearXNG рядом с сервером, бесплатно и без ключей; страницы внутренней сети не открываются никогда; на странице каждого агента — выключатели «Что агенту можно» (интернет, запуск программ).

Стек: TypeScript, [Mastra](https://mastra.ai), CopilotKit 2 (AG-UI), Better Auth, LiteLLM, Postgres, Docker, Caddy.

**Состояние:** этапы 1 и 2 реализованы по спецификации [`docs/specs/[12.11.2026]-agent-base-architecture.md`](docs/specs/%5B12.11.2026%5D-agent-base-architecture.md); ход работ — задачи #1 и #2.

## Как устроено

```text
Браузер ──HTTPS──> Caddy (интерфейс; наружу только /app/api)
                     └──> приложение: свой сервер Hono + Mastra + CopilotKit runtime
                            ├──> Postgres + pgvector (схемы app, mastra, litellm)
                            ├──> LiteLLM v1.109.1 ──> провайдеры моделей и аккаунты ChatGPT (личный ключ и бюджет у каждого сотрудника)
                            ├──> песочница bubblewrap: папка разговора (в проекте — общая папка проекта), без сети
                            ├──> страницы интернета (только публичные адреса); поиск — LiteLLM ──> SearXNG
                            └──> MCP-подключения к системам организации
```

Ядро (`core/`, `web/`, `contracts/`) и общие плагины (`plugins/`) — открыты. Установка конкретной организации — это её копия репозитория, где меняется только «зона установки»: `config/`, `agents/`, `workflows/`, `skills/`, `custom/`.

## Запуск для разработки

Нужны: Node 24, pnpm 11, Docker, bubblewrap (Linux; на macOS — встроенная изоляция), [uv](https://docs.astral.sh/uv/) для Python скиллов и программы песочницы — LibreOffice, pandoc, poppler, qpdf, tesseract с русским (Ubuntu: `sudo apt install -y --no-install-recommends $(grep -v '^#' core/sandbox/apt-packages.txt)`; без прав администратора их поставит `pnpm skills:setup` в `.venv-skills`). Без них сервер не запустится и назовёт, чего не хватает.

```bash
pnpm install                 # заодно включает проверку перед отправкой (нет ли данных заказчиков)
cp .env.example .env         # заполните: секреты — openssl rand -base64 48, ключ шифрования — openssl rand -base64 32
pnpm skills:setup            # библиотеки Python, пакеты Node и недостающие программы для скиллов документов
pnpm dev:db                  # Postgres, LiteLLM с моделями-заглушками и почтовый сервер для тестов
```

Демо с настоящей моделью:

```bash
pnpm dev                                         # LiteLLM установки, сервер (:3000) и интерфейс (http://localhost:8080)
pnpm dev:people                                  # те же люди, что на стенде: igor@ (суперадмин), olga@, petr@example.com, пароль correct-horse-battery
```

Для своей почты вместо `dev:people` — `pnpm admin:create you@example.com "Ваше Имя"` (печатает ссылку-приглашение суперадминистратора).

Откройте ссылку, задайте пароль. Скиллы документов (Word, Excel, PowerPoint, PDF) уже стоят — они встроены в ядро. В «Нейросети» добавьте модель: провайдер и модель (`openai/gpt-4.1-mini`), ключ провайдера, цены в рублях — сервер проверит ключ и передаст модель в LiteLLM; выберите её основной. Затем в «Отделах» создайте отдел, добавьте себя и агента «Общий помощник» — он появится в «Агентах».

Для сквозных проверок в браузере (`pnpm test:e2e`) — стенд с моделью-заглушкой, которая отвечает по ключевым словам («таблица», «график», «карточка», «выбор», «форма», «калькулятор», «сломанный», «письмо», «сделки», «почтальон», «документ Word»). Он занимает те же порты, что и `pnpm dev`, поэтому запускать их одновременно нельзя:

```bash
pnpm stand       # сервер на свежей тестовой базе (удаляется при остановке)
pnpm dev:web     # интерфейс: olga@example.com, petr@example.com или igor@example.com, пароль correct-horse-battery
```

## Проверки

```bash
pnpm typecheck && pnpm lint && pnpm test   # обязательные: типы, правила и границы импорта, тесты сервера и интерфейса
pnpm test:e2e                              # сквозные сценарии в браузере на стенде с моделью-заглушкой
pnpm smoke                                 # сборка образов и проверка установки в Docker
pnpm check:public                          # вся история — без данных заказчиков
```

## Установка у организации

`deploy/compose.yaml`: Postgres, LiteLLM (стандартный образ, закреплён по digest), приложение с песочницами, Caddy — с потолками памяти, чтобы всё помещалось на сервер 8 ГБ. Файлы входа аккаунтов ChatGPT лежат в томе `chatgpt-auth`, общем для приложения и шлюза; копия токенов — зашифрованной в базе.

```bash
cp deploy/.env.example deploy/.env          # заполните
docker compose -f deploy/compose.yaml up -d --build --wait
docker compose -f deploy/compose.yaml exec app node core/cli/admin.ts create admin@example.com "Администратор"
```

Подробно — [копия для заказчика](docs/guide/customer-copy.md). Как написать плагин — [docs/guide/plugins.md](docs/guide/plugins.md).

## Структура

```text
core/        ядро: сервер, вход и роли, чат, подтверждения, фоновые задачи, модели и лимиты, маскирование, подключения, песочница
web/         интерфейс: чат, виджеты, «Ждёт подтверждения», настройки, админка
contracts/   схемы данных, общие для сервера и интерфейса
plugins/     общие плагины (в шаблоне — пример example-notes)
config/      настройки установки: организация, плагины (модели — в «Нейросети» админки)
agents/      агенты установки (в шаблоне — «Общий помощник»)
deploy/      Docker: образы, compose, Caddy, профиль seccomp, smoke.sh
tests/       демо-установка, стенд и сквозные сценарии
tooling/     проверки границ импорта, данных заказчиков, сборка профиля seccomp
```
